# 高顿讲义整理规范

## 用途与边界

本规范用于把高顿讲义整理成**完整复习版**：用自己的话覆盖全部实质性考点，帮助理解和复习。它不是逐页转录，也不是只列公式的考前速查。

- 仓库：`YushuZhi96/CFA-Level-1-Notes`。所有课程资料及其衍生整理留在 `高顿资料/` 内。
- 原有科目目录、个人笔记、总目录和模板不移动、不重命名、不改写。
- 不把整理者的解释写成用户的理解、错因或学习进度；个人心得仅在用户明确要求收录时写入原个人笔记体系。
- 课程归档年份仅用于分类，不代表已核对该年官方考纲。PDF 元数据时间也不能单独作为版本结论。

## 目录和命名

```text
高顿资料/
├── 讲义整理规范.md
└── <年份>-<课程名称>/
    └── <科目中文名>/
        ├── <原始文件名>.pdf
        └── <科目中文名>-考点整理.md
```

每科默认一份 Markdown，按讲义章节顺序整理并提供页内目录。原版 PDF 保持原名和原始字节，不覆盖其他版本。同科目后续内容合并到现有整理，保留可辨认的来源和日期；新版本讲义并存时明确版本，不混用页码。

## 文档元信息

开头记录 `type: study-summary`、科目、原始文件名、PDF 总页数、课程归档年份、整理日期、状态、标签。正文说明它是衍生复习笔记而非原文，提供原 PDF 相对链接。

页码统一指 PDF 阅读器从 1 开始显示的物理页码，不用幻灯片印刷页码替代。每个考点写 `来源：PDF p. X–Y`，涉及多处来源时列出全部页码。

## 考点模板

```markdown
### 考点名称（English Term）

**来源**：PDF p. X–Y。

**一句话理解**：……

**核心概念**：……

**公式与适用条件**：……

**易混对比与考试陷阱**：……

**例题方法**：……
```

- 中文解释保留关键英文术语；比较关系用 Markdown 表格。
- 公式采用 LaTeX，注明变量、期间、平均值/期末值、单位、符号和适用条件。没有公式的考点省略该栏。
- 原讲义有例题：概括题意、关键数据、计算步骤和结论，不大段复制题干、选项或解析。
- 原讲义无例题：明确写“讲义未附例题”；可提供标注为“补充理解”的判断路径或自拟例子，不冒充原题。
- 原页只列标题时，不把补充讲解伪装为原文；标明补充范围。
- 不凭经验给内容贴“必考”“高频”标签；没有可核对依据时只说明它的用途。
- IFRS / US GAAP 的差异以及资产、利润、现金流、比率的方向，必须同时给出前提。
- 疑似原文错误用“原页表述 / 核对结论 / 理由”分开记录；不能确定的列为“待核实”，不得静默修正。

## 操作步骤

1. 开始前读取本规范，检查 Git 状态及远端，保留已有未提交修改；确认目标文件与来源版本。
2. 检查 PDF 页数和文本层；先列出逐页内容及章节/考点清单。图片页 OCR，完整阅读 OCR 结果。
3. 对照原图检查公式、表格、图示、数字、上下标、正负号和阅读顺序；不能辨认的留明确标记和页码。
4. 按章节逐项写作，不因篇幅长而省略后半部分。补充解释均与讲义内容区分。
5. 独立复算例题，检查条件和计算口径。没有官方答案时区分“讲义答案”与“复算结论”。
6. 文末维护章节覆盖表（章节、页码、考点、整理情况）及待核实清单。中断时标记已完成范围，续做前先读覆盖表。
7. 检查 Markdown、链接、公式、覆盖率及 Git 差异；只暂存本任务文件，提交并推送，返回 GitHub 文件链接及未解决事项。

## 验收清单

- [ ] 每个实质性章节与考点均有整理和来源页码；封面、宣传、目录等页面说明用途或略过原因。
- [ ] 所有公式和复杂表格经过原图核验，例题经过独立复算。
- [ ] 条件、准则差异和单位明确；解释性补充与原讲义可区分。
- [ ] 无乱码、空白占位或把待办当完成的条目；不明内容明确列出。
- [ ] 标题层级、目录锚点、表格、LaTeX 和本地来源链接正确。
- [ ] 原版 PDF 字节未改变；提交只涉及授权的高顿资料文件。
- [ ] GitHub 推送完成；最终说明实际完成范围，不声称已做未执行的年度考纲核对。
